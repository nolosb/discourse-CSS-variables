Naming scheme · draft · 6 Oct 2026

Rules

One naming system for every CSS custom property in core, themes and plugins. Each name says which layer it belongs to, who owns it and what it is for.

Checked against core at 68ad0815c02: 686 custom properties in core stylesheets, 192 more in bundled plugins.

01Layers and prefixes

LayerPrefixOwnerVisibility
System (semantic)--d-sys-Corepublic
Core component--d-comp-{Component}public
Theme--t-{ThemeName}public
Theme component--tc-{ComponentName}public
Plugin--p-{PluginName}public
Base (palette, raw scales)openCorenot public
--d-

--d- belongs to core. Extensions may set public --d-sys- and --d-comp- tokens; that is the customization contract. They never define new names under --d-.

  • Every name in these layers is public: documented and stable. A rename goes through the renaming framework and the old name keeps resolving. The base layer is the only part that is not public.

02Anatomy

The order is fixed. Slots can be left out but never moved. PascalCase marks the owner; everything else is lowercase and drawn from closed lists.

--d-sys-{category}[-{property}][-{role}][-{variant}][-{state}]
--d-comp-{Owner}[-{part}]-{category}[-{property}][-{role}][-{variant}][-{state}]
--{t|tc|p}-{Owner}[-{Component}][-{part}]-{category}…

03Grammar

Slots

Rules

  • property, role and variant are only allowed where the vocabulary lists them for that category.
  • Two states go condition first, interaction second: selected-hovered, never hovered-selected.
  • A part may not be a word from any closed list, so border can never be a part.
  • Hyphenated entries such as line-height or inline-end fill one slot, so font-line-height-body has four segments but three slots.
  • If a property has roles, the role slot is always filled and the neutral role is spelled default. Scales have no role. Size scales use md as their middle step; spacing counts 4px steps.

04Components

--d-comp-{Owner}[-{part}]-{category}[-{property}][-{role}][-{variant}][-{state}]

Owner comes from the file path

Class names in core are not reliable: topic-list/item.gjs exports Item and header.gjs exports GlimmerHeader. The path is unique and an agent can derive it: take the path under app/components/ or app/ui-kit/, split on / and -, capitalize each word and join.

FileOwner
ui-kit/d-button.gtsDButton
ui-kit/d-toggle-switch.gjsDToggleSwitch
sidebar/section-link.gjsSidebarSectionLink
topic-list/item.gjsTopicListItem
header/home-logo.gjsHeaderHomeLogo
post/menu.gjsPostMenu
  • The D comes from the d- file names in ui-kit/. Eight components outside ui-kit also start with d- (d-navigation, d-section, …), so D alone does not prove ui-kit.
  • Styles with no component file (global input styles, .nav-pills, tables) use a registered pattern name: Input, NavPills, Table.
  • Same shape as system tokens. After the owner and an optional part, a component token follows the system grammar, so one can be read from the other: --d-sys-color-text-muted and --d-comp-TopicListItem-color-text-muted.
  • Kinds go in the role slot. A component's kind takes the position of the role. DButton kinds are default, primary, danger, success, flat and transparent: --d-comp-DButton-color-background-primary-hovered.
  • Part is one word for an element that has no component file (DModal-header, PostMenu-button). If the element has its own file, use that file's Owner.
  • A part is also used for a style the owner applies to many child components at once: PostMenu-button styles all 13 post menu buttons, which each have their own file. Use a child's own Owner only for tokens that apply to that one child.
  • Extra properties: components can use a few words system tokens never use, such as logical sizes (size-max-inline for a max width) and spacing axes (space-padding-inline). See Categories and properties and Roles in components.
  • Role and variant may be left out when the component holds a single value: --d-comp-DButton-border-radius.
  • All component tokens are declared on :root, like system tokens. A theme can override any of them in one :root block, and an agent always knows where to look. Scoped overrides on component selectors stay allowed.

05Extensions

--{t|tc|p}-{Owner}[-{Component}][-{part}]-{category}…
  • Owner: PascalCase of the name in about.json, or of # name: in plugin.rb with a leading discourse- removed. Horizon, DiscoverySidebar, Chat, Reactions, Ai.
  • Component (optional): the extension's own component, derived from its path like core: --p-Chat-ChatComposer-color-background.
  • Bundled plugins are plugins. Chat's --d-chat-input-bg-color becomes --p-Chat-ChatComposer-color-background.
  • Extensions read public --d-sys- and --d-comp- tokens and may override them, globally or in a scope.
