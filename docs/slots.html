Naming scheme

Slots

How a name is built from the vocabulary, one slot at a time. The word lists on this page are read from vocabulary.json.

SlotCasingRequiredWords
prefixlowercaseyesprefixes
OwnerPascalCaseyes, except in sysderived from the file path or extension name
ComponentPascalCaseno, extensions onlyderived from the extension's component path
partlowercaseno, max one, not in sysfree word; known ones in parts
categorylowercaseyescategories
propertylowercaseper categorycategories.*.properties
rolelowercaseper propertyroles per property; kinds, axes in components
variantlowercaseper propertyvariants
statelowercaseno, max twostates

The order is fixed. Slots can be left out but never moved. PascalCase marks the owner; everything else is lowercase. Words with a hyphen, such as line-height or inline-end, fill one slot, so font-line-height-body has four segments but three slots.

--d-sys-{category}[-{property}][-{role}][-{variant}][-{state}]
--d-comp-{Owner}[-{part}]-{category}[-{property}][-{role}][-{variant}][-{state}]
--{t|tc|p}-{Owner}[-{Component}][-{part}]-{category}…

01prefix

The prefix says which layer a name belongs to.

LayerPrefixOwnerVisibility
System (semantic)--d-sys-Corepublic
Core component--d-comp-{Component}public
Theme--t-{ThemeName}public
Theme component--tc-{ComponentName}public
Plugin--p-{PluginName}public
Base (palette, raw scales)openCorenot public
  • --d- belongs to core. Extensions may set public --d-sys- and --d-comp- tokens; that is the customization contract. They never define new names under --d-.
  • Every name in these layers is public: documented and stable. A rename goes through the renaming framework and the old name keeps resolving. The base layer is the only part that is not public.
  • System and component tokens are declared on :root. A theme can override any of them in one :root block, and an agent always knows where to look. Scoped overrides on component selectors stay allowed.

02Owner

The Owner says whose token it is. System tokens have none: --d-sys- already means core.

Core components: from the file path

Class names in core are not reliable: topic-list/item.gjs exports Item and header.gjs exports GlimmerHeader. The path is unique and an agent can derive it: take the path under app/components/ or app/ui-kit/, split on / and -, capitalize each word and join.

FileOwner

  • The D comes from the d- file names in ui-kit/. Eight components outside ui-kit also start with d- (d-navigation, d-section, …), so D alone does not prove ui-kit.
  • Styles with no component file (global input styles, .nav-pills, tables) use a pattern name from patterns: .

Extensions: from the extension name

PascalCase of the name in about.json, or of # name: in plugin.rb with a leading discourse- removed: Horizon, DiscoverySidebar, Chat, Reactions, Ai. Bundled plugins are plugins: chat's --d-chat-input-bg-color becomes --p-Chat-ChatComposer-color-background.

03Component

Extensions only, and optional: the extension's own component, derived from its components/ path like a core Owner. --p-Chat-ChatComposer-color-background, --t-Horizon-TopicCard-shadow. Without it, the token belongs to the extension as a whole: --t-Horizon-color-background-raised.

Extensions read public --d-sys- and --d-comp- tokens and may override them, globally or in a scope.

04part

One lowercase word for an element inside a component that has no component file of its own: --d-comp-DModal-header-…, --d-comp-NavPills-underline-size-block. If the element has its own file, use that file's Owner instead (SidebarSectionLinkPrefix).

  • A part is also used for a style the owner applies to many child components at once: PostMenu-button styles all 13 post menu buttons, which each have their own file. Use a child's own Owner only for tokens that apply to that one child.
  • A part may not be a word from any list, so border can never be a part.
  • Parts are free words. The ones in use are listed under parts, so agents reuse them; a new part gets added there in the same change.

05category

The first lowercase word after the owner (or part) is the category: what kind of value the token holds. Every name has one.

06property

The property says what inside the category the token sets. shadow and opacity have no property; the role follows the category directly.

CategoryPropertiesComponents may also use

Component sizes use logical axes like CSS inline-size and block-size: in horizontal text inline is the width and block the height. --d-comp-DModal-size-max-inline is the modal's max width.

07role

A role says what a value is for. In --d-sys-color-text-muted, muted is the role. If a property has roles, the role is always written, and the neutral one is default. Properties that are pure scales (font-size, space-*, border-radius) have no role and go straight to the variant.

  • A system token always describes a purpose or level, never a UI component: shadow-overlay, not shadow-dropdown. The one exception is input, because form fields share one look across every component that has them.
  • accent replaces tertiary. warning and info have no color of their own in core yet: warnings borrow the highlight color (--highlight-bg) and info borrows the accent (--tertiary-low, so info-subtlest). Their tokens can start with those values and get their own colors when the base colors are redesigned.

In components: kinds

A component's kind takes the role slot: --d-comp-DButton-color-background-primary-hovered. Kinds are a closed list per component under kinds; the checker rejects any other word.

OwnerKinds
  • One role word. A kind replaces the role and never combines with it, so there is no DButton-color-text-primary-muted. If an element inside the component needs its own color (a count next to the label), it is a part: --d-comp-DButton-count-color-text-primary.
  • A modifier that gives a kind its own full set of colors is a kind of its own: .btn-flat.close becomes the close kind (--d-comp-DButton-color-icon-close-hovered), not a part, because it is not an element inside the button.
  • Role and variant may be left out when the component holds a single value: --d-comp-DButton-border-radius.

In components: axes

Spacing tokens can put an axis in the role slot to say which side the value applies to: . --d-comp-SidebarSectionLink-space-padding-inline. gap takes only inline or block (column or row gap).

08variant

A variant is a step on a scale. There are four scales, and each property uses at most one of them.

ScaleWordsUsed byRules
sizefont-size, size-*, border-radius, border-width, motion-durationOne scale for everything except spacing. md is the middle step. Never large, small or default. border-radius also takes full.
stepspace-*Counts 4px units: 2 is 8px, 5 is 20px.
strengthcolor-*, after an intent or a component kindOnly follows an intent or a kind (danger-subtle, DButton primary-subtle, never muted-subtle). The base strength has no word.
weightfont-weightNamed CSS weights.

Strength steps

Faintest to strongest:

StepLooks likeExample
subtlestfaintest tint, e.g. a banner background--d-sys-color-background-danger-subtlest
subtlemid tint--d-sys-color-background-danger-subtle
the standard intent color, no suffix--d-sys-color-background-danger
boldstronger than the base--d-sys-color-background-accent-bold

Today's shades map by how far core lightens them toward the page background: 80–93% is subtlest, 40–74% is subtle, 0–30% is the base. -hover shades are the hovered state, not a strength. bold has no value in core yet. Each old variable's target is in mapping.md.

Space steps

Spacing counts 4px units, the same as core's --space-N today, so every current value keeps a step: --d-sys-space-padding-5 is 20px. Spacing needs finer steps than size words give, like most larger systems (Tailwind, Polaris, Atlassian, Primer).

09state

States are past participles; the rest state is never written. At most two, condition first and interaction second: selected-hovered, never hovered-selected.

KindWordsNotes
Conditiondisabled is a state, not a role. active is not allowed; use pressed, current or selected.

10Values

  • A color token always holds a full color. There are no -rgb twins (--secondary-rgb and similar, which exist today only to add transparency). Apply transparency with color-mix(): color-mix(in srgb, var(--d-sys-color-background-default) 80%, transparent).
  • Light and dark are never in a name. Values use light-dark() or are swapped per color scheme: --d-sys-color-text-default is one name in both modes.
  • A shadow token names the job, not the technique: shadow-overflow holds a 1px hairline even though it is drawn with box-shadow.
